# ScreenOhRecord 1.2.1 architecture

Approved scope/decisions are recorded in RELEASE-PLAN-1.2.0.md and project AGENTS.md. The user approved an independent recorder rather than redistribution of AZ Recorder. Original source, branding and signing key are retained. Personal use, small GitHub release assets and Android 16 verification are the current scope; no ads/analytics/livestreaming/internal-audio mixing/video editor is introduced.

## Recording and deletion

Framework-only Java, minimum API 29, target/compile API 36; pinned Gradle 8.11.1/AGP 8.10.1. RecordingOptions owns private, versioned capture preferences. Existing bitrate/microphone defaults and later choices are retained. Resolution caps are 720/1080 short-edge with even dimensions/no upscaling; fps targets 15/30; video bitrates 250/350/500 kbps and 1/2/4/6 Mbps; optional microphone AAC 96kbps/44.1kHz. H.264, HEVC/H.265 and AV1 map to their MediaRecorder codecs. AV1 requires API 33+; all requested formats are checked against device encoder capabilities before output creation. Selection is explicit and an unavailable codec fails clearly rather than silently substituting another codec.

CaptureActivity snapshots settings, obtains runtime permissions and fresh Android consent, and remains visible until the recorder enters its microphone/mediaProjection foreground session. API 34+ requests the default entire display. No token persistence/reuse or automatic restart. RecordingService owns MediaProjection/VirtualDisplay/MediaRecorder and encodes directly into an owned local descriptor; it never inspects screen text or uploads frames. Pause/resume operate on the encoder; screen-off/revocation/service teardown finalize or discard output. Rotation keeps the initial recording canvas.

Default storage is a pending scoped MediaStore item in Movies/ScreenOhRecord. Optional local folders must use com.android.externalstorage.documents and grant persistent access; cloud providers are excluded. Files must be seekable for MP4. Storage failure is explicit, without silent fallback. No broad media/storage permission or library scanning. Private synchronous unfinished/finalized markers enable cleanup without deleting a finalized file after a history-write interruption. History is limited to 50 entries; leaving history does not erase older videos.

The floating specialUse foreground service is explicitly enabled with overlay permission, display/window-context bound and state-change driven. It hides during capture consent and persists its position; no idle capture/polling or boot restart. Stop and Delete dispatches DISCARD only for the active session. The encoder is stopped/released, the descriptor closed, and the pending file deleted directly through MediaStore or DocumentsContract. No history publication or trash request occurs. The floating menu remains open on successful deletion and errors; errors retain cleanup state and remain visible. Hide bubble alone does not stop recording. Existing saved entries are not affected by DISCARD.

## Updater trust boundary

The approved updater supersedes the earlier no-INTERNET manifest guarantee. INTERNET, ACCESS_NETWORK_STATE, REQUEST_INSTALL_PACKAGES and RECEIVE_BOOT_COMPLETED are added. There are still no advertising/camera/broad media permissions. The main launcher alone is externally exported as an app screen. The update JobService is exported only under system-signature BIND_JOB_SERVICE; capture/settings/update hosts and recording services are non-exported.

UpdateClient is the sole network implementation and has no RecordingStore dependency. It performs bounded GET requests to a fixed repository's public GitHub release manifest/APK. Redirects require HTTPS, no URL credentials/custom ports and exact github.com/release-assets.githubusercontent.com/objects.githubusercontent.com hosts. Metadata schema, stable version format, APK's exact repository/tag/name URL, size limit and checksum shape are checked. Metadata reads are capped at 64KB; APK at 100MiB and its exact expected size; timeouts/redirect counts are bounded. A private partial file is removed on failure; a verified APK stays in private app files, never the gallery. No credentials are embedded in the app.

Before installation the APK is rechecked for size/SHA-256, exact package/name/version/newness, supported minimum SDK and reported signing certificates matching the installed app. Android PackageInstaller performs platform signature verification and explicitly requests user action. The update screen obtains allow-from-this-source access if needed, then uses a mutable, explicitly targeted activity PendingIntent for installer status. Installation approval remains Android UI. Cancel/error is displayed; successful installation retains app data and removes the cached installer when its success callback is received.

A synchronized operation gate prevents updater requests while recording/capture consent is active and prevents new capture while checking/downloading/installing. Requests are user-driven or the optional weekly job; no startup check is performed. Weekly scheduling defaults off, is persisted across reboot only when enabled, uses an unmetered-network requirement and independently selects Wi-Fi. Its HTTP connection is bound to that network so it cannot silently reroute to mobile data when Wi-Fi disappears. It fetches metadata only, saves last result, and can notify if Android notification permission is granted. Android may delay execution. Disabling cancels the job; stopping a job cancels its worker. It never downloads/installs an APK.

App data backup/device transfer remains disabled. Other gallery/player/backup apps may sync shared videos under their own permissions. Public GitHub receives normal update HTTP requests (including IP/user-agent/app version), but never recordings, screen text or device media from this app.

## Release workflow and verification

build.ps1 creates a signed release plus checksum with the preserved private .local-signing key. The same signer enables in-place upgrades. Optional Gradle version properties generate a local older-version updater fixture; it is not published. Test APKs, runtimes, analysis, caches, recordings and signing material are excluded from Git.

scripts/publish-release.ps1 requires matching successful verification JSON/hash and a clean-failure-free test log; checks the signature and repo identity; establishes a dedicated project Git repository preserving existing remote history; stages only explicit source paths; pushes source and a version tag; creates a draft Release; uploads the APK/checksum/update.json; and publishes only after upload-size checks. Existing release versions are never overwritten. Git credential-manager credentials stay in memory and are sent only to GitHub's APIs, not written to source/logs. No parent C:\Users\Mike Git repository is staged or pushed.

Framework-only instrumentation covers actual recording/playback, all low bitrates, optional overlays, default/custom-folder permanent discard, AV1, update metadata/checksum/version/signature rejection, scheduling and operation exclusion. Live public-release/download/PackageInstaller testing follows publication. See TESTING.md and local artifacts for exact identity, logs and limitations. Emulator results do not guarantee all phones, hardware codecs/removable media or future Android releases.

## 1.2.1 recording previews and installed version

MainActivity shows the installed PackageInfo version name/long version code as the final root-layout element, refreshing on resume with generated BuildConfig fallback. A version bump therefore appears without editing a separate text label.

RecordingThumbnails uses one worker, scaled MediaMetadataRetriever frames, a 4 MiB LruCache and weak ImageView bindings. Decoding reads only owned/granted local recording URIs; it does not use provider thumbnail APIs that could populate separate on-disk image caches. No preview file or broad media permission is introduced. Row rebuilds invalidate pending requests; request-identity and URI-tag checks prevent late frames from attaching to deleted/rebound views or refilling deleted cache entries. Confirmed deletion invalidates cache/work and clears the image before rebuilding history. Activity destruction cancels work and evicts memory references. An unreadable video keeps a placeholder without blocking the UI.

## 1.2.2 recording-history reconciliation

On resume, a dedicated worker checks saved entries against accessible local storage. MediaStore uses an exact-URI query; custom destinations require a readable tree root and a successful children query before declaring a document absent. Null cursors, provider errors, revoked permission and unavailable primary storage preserve entries. Only confirmed missing entries are removed; reconciliation never deletes video files. Removed entries evict previews, and row rebuilds clear detached images. This is a resume check, not continuous folder monitoring.

Delete accepts an already-missing URI and rechecks availability after a provider deletion failure, covering disappearance during confirmation. Other failures retain history. A shared lock protects history read/modify/write against concurrent recording completion. Thumbnail storage remains memory-only. No permissions, dependencies or network behavior change.

## 1.2.3 automatic floating controls

MainActivity.onResume starts the existing floating-control service when Display over other apps is allowed and the service has no visible bubble. The service's existing root guard avoids duplicate windows. Hide still stops the service and is not undone by the UI refresh timer; the next main-screen resume restores it. Missing/revoked permission leaves ordinary app controls available, with inline instructions and the existing explicit Show floating controls permission flow. Resume never requests capture consent or starts recording. No boot behavior, permissions or network behavior change.
